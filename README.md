# X1 BASIC Editor

X1 のアスキーセーブ BASIC を、X1 のドット字形で編集する小さなデスクトップエディタです。Windows / macOS / Linux で同じソースを使います。ファイルの内容を Shift-JIS や UTF-8 として自動変換しません。

## 起動

Windows のビルド済みポータブル版は [GitHub Releases](https://github.com/ho-ogino/x1-basic-editor/releases/latest) から取得できます。インストールは不要です。手元でビルドした場合は `dist/X1 BASIC Editor 0.2.0.exe` に出力します。

ソースから起動する場合は Node.js 24 LTS 以降と npm を使用してください。

```sh
git clone https://github.com/ho-ogino/x1-basic-editor.git
cd x1-basic-editor
npm ci
npm start
```

最初の起動では Electron の公式バイナリをダウンロードする場合があります。その後の編集にネット接続は不要です。

起動時にファイルを指定することもできます。

```sh
npm start -- test/fixtures/editor-sample.bas
```

起動ファイルの読み込み完了前に入力・新規作成・別ファイルを開く・保存を行った場合は、起動時の読み込み結果を採用せず、その操作を優先します。遅れて読み終えたファイルで編集中の文書を置き換えません。

Windows では `start.cmd` も利用できます。初回だけ `npm ci` を実行しておいてください。

## 操作

- 通常のメモ帳と同じように選択・入力・削除できます。ASCII の英数字は通常の単語選択も可能です。
- 右のパレットで、記号・カナ・制御コード・全256コードを選択できます。クリックすると選択範囲を置き換えます。
- 編集欄と右欄の境界を左右にドラッグすると、右欄の幅を調整できます。境界にフォーカスして左右キーでも調整でき、Homeで既定幅へ戻せます。調整した幅は起動中だけ保持し、文字パレットとPCG一覧の切り替えでも引き継ぎます。
- 上部の「右欄を隠す」で記号・PCGの欄と境界を畳み、編集欄を広げられます。「右欄を表示」で選んだ幅に戻り、折り返しも再計算します。起動時は右欄を表示し、畳んだ状態でウィンドウ幅を変えても希望幅は保持します。
- 単独アプリのファイル操作は「開く」「保存」です。「保存」は現在のファイルを上書きし、別の保存先を選ぶには「別名で保存」を使います。X1Penなどの埋め込み先では「インポート」「エクスポート」と表示します。
- 単独アプリでは編集中のファイル名と「保存済み／未保存の変更」を表示します。編集・Undo・保存に追従し、別名保存後は新しい名前になります。ウィンドウタイトルの未保存印と閉じる前の確認も使います。X1Pen内ではこの状態表示を出しません。
- カーソル位置のコードと名称を下部に表示します。
- HuBASIC の予約語は青、数値は緑、文字列は橙、コメントは緑灰色で表示します。変数は通常色、行頭のBASIC行番号は控えめな灰色です。`REM` と `'` のコメント、空白を省いた予約語、小数・指数・16/8/2進数、DATA の生テキストを判別します。色分けによってソースの文字・大文字小文字・バイト列を書き換えません。
- 編集欄上部の「右端で折り返す」で、見えている幅に合わせて表示を折り返せます。ウィンドウ幅や文字倍率の変更に追従し、継続する表示行の左には `↪` を表示します。保存するバイト列や改行コードは変わりません。下部の行・桁は元のソース上の位置です。
- 文字倍率は 1×・2×・3×・4× に対応し、起動時は 2×、右端での折り返しは ON です。
- 折り返しでは単語・句読点・引用符まわりの禁則処理を使わず、記号や空白も含めて1文字単位で右端まで使用します。実ファイルの改行は追加しません。
- カナは半角・全角・ひらがなから入力できます。濁点・半濁点は X1 の2バイトに変換します。
- 対応しない漢字・絵文字などは、入力全体を反映せず通知します。勝手な代替文字への置換は行いません。
- 青い文字は制御コードです。編集画面で制御動作を実行しません。例えば `$1D` は左矢印の字形で表示します。
- `$0D`、`$0A`、`$0D $0A` は改行として表示し、それぞれのバイトは保持します。全コードを見せる16進ダンプ画面ではありません。
- Tab キーは、1セル表示の `$09` を挿入します。スペースには展開しません。
- 「コード・記号名で挿入」では `\x87`、`\{heart}`、`\{LEFT}` などを入力できます。バックスラッシュ自体は `\\` です。
- 検索・置換でも同じエスケープを使用できます。通常の入力・貼り付けではエスケープを解釈しません。
- アプリ内のコピー＆ペーストは独自クリップボード形式で元のバイトを保持します。他のアプリへは、記号と制御コードをエスケープ表記にしたテキストを渡します。他アプリを経由すると独自形式が失われるため、バイトの完全保持が必要な場合は直接貼り付けてください。
- 下部の「新しい改行」は、これから入力する改行だけに適用します。既存の改行を一括変換しません。初期値はファイル内で最も多い形式（空ファイルは CRLF）です。
- Undo / Redo はバイト列のスナップショットを保持します（最大200操作）。「すべて置換」も1回の Undo で戻ります。

| 操作 | Windows / Linux | macOS |
|---|---|---|
| 開く（埋め込み先ではインポート） | Ctrl+O | ⌘O |
| 保存（埋め込み先ではエクスポート） | Ctrl+S | ⌘S |
| 別名保存 | Ctrl+Shift+S | ⌘Shift+S |
| 元に戻す / やり直す | Ctrl+Z / Ctrl+Shift+Z | ⌘Z / ⌘Shift+Z |
| 検索 | Ctrl+F | ⌘F |
| 次 / 前を検索 | F3 / Shift+F3 | F3 / Shift+F3 |
| コードで挿入 | Ctrl+I | ⌘I |

## 保存の仕組み

編集用の表示とファイルのバイト列を分離しています。印字可能 ASCII 以外は Unicode の私用領域に1対1で対応させ、アプリ専用フォントで描画します。改行にはバイト位置の対応表を持ち、編集した範囲以外を元のバイト列から引き継ぎます。BOM の付加、末尾改行の補完、タブ展開、自動整形を行いません。

保存時は同じディレクトリの一時ファイルに書き込み、同期してから置き換え、再読み込みしてバイト一致を検証します。上書き前のファイルは初回だけ `元の名前.bak` に保存します。既存の `.bak` は上書きしません。読み込み・前回保存以降に他のアプリが変更・削除したファイルへの上書きは拒否します。別名保存で退避してください。

一般的なローカルファイル向けです。保存中の停電やストレージ故障までを保証するものではありません。

## 独自フォント

右側の「表示フォント」→「.X1 を読み込む…」、またはメニューの「表示」→「X1フォントを読み込む…」から、`FNT0808.X1` などの 8×8 ANK フォントを選択します。

- 形式：ヘッダーなしの 2,048 バイト（256文字 × 8行）。1文字につき連続した8バイトで、各行の上位ビットが左端、1が点灯です。
- 編集欄・文字パレット・文字のプレビューに反映します。BASIC の文字コードとファイル内容は変わりません。
- フォントデータ自体をアプリの設定領域の `display-settings.json` に保存します。次回起動時に復元するため、読み込み元のフォントファイルを移動しても使えます。
- 「内蔵に戻す」で標準フォントへ戻せます。この選択も次回起動に引き継ぎます。
- サイズ違いのファイル、フォントの表示や設定保存の失敗では、それまでのフォントを保持します。
- 文字倍率・折り返しの起動時の初期値は、毎回 2×・ON です。

アプリ内での表示に使用し、OSへのフォントのインストールは行いません。読み込んだ個人用フォントを配布版やソースアーカイブへ同梱しません。

内蔵フォントは、美咲フォント由来の [X1互換フォント](https://github.com/meister68k/X1_compatible_font) です。実機のCG-ROMは同梱していません。旧名「X1 Byte Editor」で保存した独自フォント設定は、改名後の設定がまだなければ初回読み込み時に引き継ぎます。

## PCG定義の確認

ソース内の定義を選択し、右上の「選択からPCG設定」、または「編集」→「選択からPCG設定」（Ctrl+Shift+P / ⌘Shift+P）を実行します。複数行をまとめて選択できます。

```basic
7010 DEFCHR$(65)=HEXCHR$("80402010080402010102040810204080AA55AA55AA55AA55")
```

- この形式は指定した文字コードへ直接登録します。文字コードは0〜255の定数（10進数・`&H`・`&O`・`&B`）に対応します。`DEFCHR$(65)=STRING$(24,255)` の定数による塗りつぶしにも対応します。
- DATA文などの48桁の16進データも検出します。こちらはダイアログで開始文字コードを指定し、検出順に連続するコードへ割り当てます。確定前に先頭16件のプレビューを表示します。255を超える割り当ては拒否します。
- 同じコードが複数回出る場合は、選択範囲の後に出る定義を使います。既に登録した他のコードは保持します。コメント内のデータは読み飛ばします。
- 配列の初期値は「プレーン単位」、色順は **BRG（青8バイト→赤8バイト→緑8バイト）** です。ローカルのHuBASICランタイムの `DEFCHR$` 実装に合わせています。各プレーンは上から8行、各バイトの最上位ビットが左端です。
- 「行単位（3倍速・2桁ずつ）」では、1行ごとに青・赤・緑の各1バイトを読みます。例えば `AA55FF` は B=`AA`、R=`55`、G=`FF` です。色順は6通りから変更でき、登録済みの全定義をその並びで読み直します。
- 設定後は「PCG一覧」タブを開き、自動で「PCG ON」にします。16×16のグリッドは左上が0、右下が255です。定義済みの画像をクリックすると、カーソル位置へその文字コードを挿入します。選択中はその範囲を置き換え、Undoで戻せます。あわせてコード・拡大図・元の16進データも表示します。未定義のセルは詳細表示のみです。個別解除と全解除もできます。
- 「PCG表示は文字列のみ」は起動時ONです。PCG ON中でも、編集欄では引用符の内側だけをカラーPCGへ差し替えます。引用符自体・予約語・変数名・行番号・コメント・引用符のないDATAは通常の字形です。文字列を編集すると表示範囲も更新します。このチェックをOFFにすると、従来どおりソース全体の該当コードをPCG表示します。
- 選択の背景色もソースの表示層へ描くため、文字列のみモードでも、選択中のPCGは同じ字形のまま表示します。選択範囲は入力・Undo・検索・フォーカス移動に追従します。
- 文字パレットとPCG一覧は、文字列のみの設定にかかわらずPCGの字形を確認できます。「PCG ON」をOFFにすると編集欄・文字パレットは元のフォントへ戻ります。未定義の文字は、読み込んだ独自フォントまたは内蔵フォントを使います。
- 一覧の背景は黒です。編集欄では消灯ピクセルが透過し、編集欄の背景色が見えます。行間を含む文字幅・折り返しの仕組みは通常表示と同じです。
- PCG定義・配列・色順・表示のチェック状態は、アプリを終了するまでメモリに保持します。別プログラムでPCGを定義してから別のBASICファイルを開く使い方ができ、新規作成でも引き継ぎます。「すべて解除」で明示的に消せます。ソースやフォント設定ファイルへ書き込まず、アプリ終了で消えます。定義部分を編集した場合は選択して設定し直してください。

BASICを実行する機能ではありません。変数や計算式による定義、ループや条件分岐、実行順序は評価しません。読み取れない `DEFCHR$` は通知して読み飛ばします。配列と色順の選択は全定義に共通で、異なる形式の同時表示には対応していません。

### 文字列のPCG合成プレビュー

閉じた文字列にマウスを置いて約600ms待つと、矢印の制御コードで並べ直した合成画像を表示します。PCGと通常の文字を同じように扱い、通常文字だけの文字列も対象です。例えば、3文字・下移動・左移動3回・3文字の文字列は、横3×縦2文字（24×16ドット）の画像になります。右欄を畳んでいても利用できます。

- `$1C`（右）、`$1D`（左）、`$1E`（上）、`$1F`（下）を1文字単位のカーソル移動として反映します。通常の文字を描いたあとは右へ1文字進みます。重なる場所は後の文字で1セル全体を置き換えます。
- 負の位置への移動も許し、文字を置いた範囲を画像の左上へ詰めて表示します。末尾の移動だけでは余白を広げません。画面端での自動折り返しやスクロールは行いません。
- その他の制御コード（`$00`〜`$1B`）は実行せず、幅0で省略して警告します。色属性・消去・Home・ESCの命令解釈は行いません。ESCに続くバイトも通常の規則で扱います。
- 4096バイト、描画範囲64×64文字（512×512ドット）までです。上限に達したらそこまでの画像と「以降は省略」の表示を出します。
- PCG ON時は現在の登録内容・色順・配列を使い、OFF時や未定義の文字は選択中の基本フォントで描きます。「PCG表示は文字列のみ」がOFFでも使えます。カラーコード7（白）を前提に通常字形は白、PCGは定義どおりの色、背景は黒で表示します。表示倍率は画面に収まるよう調整し、寸法は元のドット数を表示します。
- 通常文字もエディタのフォントと同じ元の8×8ビットマップを使い、PCGと同じくドットを直接描きます。OSの文字描画やアンチエイリアスを経由しません。
- マウスが外れる、クリック・キー入力・編集をする、スクロール・表示サイズ・PCGやフォント設定を変えると消えます。ソース・選択位置・Undo・保存状態は変えません。

引用符が閉じていない文字列、コメント、変数・`CHR$`・文字列連結などの式全体は対象外です。現在手動で登録した字形から単独の文字列を確認する機能で、BASICの実行結果全体を再現するものではありません。

## 制限

- 2 MiB までのファイルを対象とします。大規模なバイナリ編集用ではありません。
- PCGは選択した定数定義から手動で確認できます。プログラムを実行してPCGを追跡する機能や、漢字 ROM の表示はありません。
- BASIC の実行、構文チェック、行番号の振り直し、自動整形はありません。
- 字形の参照元・取り扱いは `THIRD-PARTY-NOTICES.md` を参照してください。

## テストとビルド

```sh
npm test
npm run build:font
npm run pack
npm run dist
```

`npm test` は、新規作成した `test/fixtures/editor-sample.bas` を合成テストデータとして使用します。既存のゲームプログラムは同梱していません。全256コード、混在改行、カナ入力、Undo / Redo、保存・バックアップ、外部変更の拒否を検証します。テスト用の出力先はこのフォルダ内の `test-output` です。SLANG-compilerのチェックアウトは必要ありません。

配布ファイルは基本的に各OSで `npm run dist` を実行して作成します。

- Windows：ポータブル `.exe`
- macOS：未署名の `.app` を含む `.zip`（Intel / Apple Silicon は対象環境でビルド）
- Linux：AppImage

Developer ID署名・公証・ストア公開は設定していません。macOS / Linux の実機確認状況は `VALIDATION.md` に記録します。

## GitHub Actionsでの配布ビルド

版番号の末尾はパッチ番号とし、不具合修正で上げます。機能を追加・変更したときは中央のマイナー番号を上げ、パッチを0に戻します（例：`0.1.x` → `0.2.0`）。

`.github/workflows/build.yml` はGitHub標準runnerで次の3種類をビルドします。self-hosted runnerは使用しません。

| 対象 | runner | 出力 |
|---|---|---|
| Windows x64 | `windows-latest` | ポータブル `.exe` |
| macOS Apple Silicon | `macos-15` | `x1-basic-editor-<version>-mac-arm64.zip` |
| macOS Intel | `macos-15-intel` | `x1-basic-editor-<version>-mac-x64.zip` |

Actions画面の「Build distributions」→「Run workflow」で実行すると、各OSのテストとビルドを行い、配布ファイルだけをArtifactとして7日間保存します。手動実行ではReleaseを作成しません。

`package.json` のバージョンと一致する `v0.2.0` などのタグをpushした場合は、3種類すべてのビルド成功後、配布ファイルと `SHA256SUMS` を添付した**下書きRelease**を作ります。自動公開はしないため、内容を確認してからGitHub上で公開してください。バージョン不一致や成果物の不足があれば作成を停止します。

macOS版はアドホック署名を付けますが、AppleのDeveloper ID署名・公証は行いません。初回起動でmacOS側の許可操作が必要になる場合があります。Developer ID署名・公証を追加する際は、別途証明書と認証設定が必要です。

## 構成

- `src/codec.js`：文字対応、バイト列、改行の位置対応、Undo / Redo
- `src/editor.js`：入力、クリップボード、記号パレット、検索・置換
- `src/syntax.js`：HuBASIC の表示用字句判定
- `src/pcg.js`：PCG定義の検出・割り当て・配列と色の解析・一覧用SVG
- `src/pcg-preview.js`：文字列内のカーソル移動を反映したPCG合成とホバープレビュー
- `src/keywords.js`：`SLANGCompiler.HuBasic/Lexing/HuKeywords.cs` から取得した186語の予約語表（コンパイラ拡張の VSYNC も含む）
- `src/file-store.cjs`：ファイルの読み書き、バックアップ、外部変更検知
- `src/font-builder.js` / `src/font-builder.cjs` / `src/font-settings.cjs`：ブラウザ共通のフォント生成・Node互換API・設定保存
- `src/host.js` / `src/sidebar-resize.js`：入れ物の接続口・右欄の幅調整
- `main.cjs` / `preload.cjs`：Electron のネイティブ操作と限定した IPC
- `scripts/build-font.cjs`：8×8ドットからアプリ専用 TTF を生成
- `assets/x1-font-source.txt`：参照文字表のドットデータ
- `assets/x1-font-provenance.json` / `assets/licenses/`：同梱フォントの取得元・固定コミット・ライセンス表記
- `.github/workflows/build.yml` / `build/entitlements.mac.plist`：標準runnerでの配布ビルドとmacOS署名設定

アプリは外部サイトや外部スクリプトを読み込まず、ネットワーク要求をブロックします。編集中のソースをサーバーへ送信しません。

## iframeへの組み込み

`src/`と`assets/`を一緒に取り込み、エディタをiframeで開きます。1ページに1つのエディタを置く構造なので、複数配置ではそれぞれiframeを使います。Electron以外では、そのiframe内で`host.js`より先にローカルのアダプター（例：`x1pen-host.js`）を読み、`window.X1Host`に下表のホスト実装を設定します。取り込み先のHTMLでこのscriptタグを追加してください。`host.js`は設定済みの`X1Host`を優先し、未設定ならElectronの`window.desktop`を使います。設定には起動前の同期処理を使い、読み込みを待つ場合はアダプター内部で待機します。

`host.js`より前に`window.X1Host`を設定した場合は、ファイル操作を「インポート」「エクスポート」と表示し、「新規」と「別名で保存」のボタンを隠します。Electronの`window.desktop`へフォールバックする単独アプリでは「開く」「保存」と表示し、「新規」と「別名で保存」も表示します。空画面の案内と保存通知も環境に合わせます。右欄の表示切り替えは両環境で使えます。ホストの`open()`・`save()`や`onCommand`の`'open'`・`'save'`など既存の名前・引数は変わりません。隠した操作のコマンドも、互換性のため引き続き呼び出せます。

```html
<!-- codec.js / keywords.js / syntax.js / pcg.js / pcg-preview.js / font-builder.js / font-bitmap.js の後 -->
<script src="x1pen-host.js"></script>
<script src="host.js"></script>
<script src="sidebar-resize.js"></script>
<script src="editor.js"></script>
```

| ホストのメソッド | 呼び方・結果 |
|---|---|
| `onLoaded(callback)` | 読み込み通知先を登録。初期データの準備後に`callback({name, bytes})`を呼ぶ。`bytes`は0〜255の配列またはUint8Array。以後の外部読み込みもこの口で渡せる。未保存確認はホストが行う。 |
| `onCommand(callback)` | コマンド通知先を登録。`callback('save')`などを呼び、返されたPromiseで完了を待てる。ボタンと同じ`new`・`open`・`save`・`save-as`・`undo`・`redo`などを使う。 |
| `open()` | `{name, bytes}`、キャンセル時は`null`を返す（Promise可）。 |
| `save({bytes, saveAs})` | `bytes`は通常の数値配列。保存できたらtruthy、失敗・キャンセルならfalsyを返す（Promise可）。このスナップショットが保存済みになる。保存の実体と名前管理はホストが担当。 |
| `confirmDirty()` | 未保存確認で`'save'`・`'discard'`・`'cancel'`を返す（Promise可）。 |
| `state({dirty})` | 現在の未保存状態を同期通知。タイトルや閉じる確認に使う。保存後も通知する。 |
| `newDocument()` / `close()` | 新規作成時のホスト側の名前等のリセット／閉じる処理。同期で受け取る。 |
| `currentFont()` | 任意。`{name, data}`を返す（Promise可）。`data`はTTFのバイト列、内蔵は`null`。 |
| `chooseFont()` | フォント候補を選び、`{name, data, token}`または`null`を返す（Promise可）。 |
| `commitFont(token)` / `resetFont()` | 候補の確定／内蔵への復帰に成功したらtruthyを返す（Promise可）。確定はフォント表示の検証後に呼ぶ。 |
| `pcgFont({entries, order, layout})` | 選択中の基本字形にPCGを重ねたTTFバイト列を返す（Promise可）。`entries`は`{code, hex}`の配列。 |
| `contentChanged({bytes, dirty})` | 任意。初期表示と、実際のバイト列が変わったときの通知。`bytes`は独立したUint8Arrayのコピー。 |

フォント操作を提供する場合は上表のフォント用メソッドを実装してください。PCG生成にはブラウザの`X1FontBuilder`を使えます。`parseFontRom(bytes)`は2048バイトのUint8Arrayから256×8の配列を作り、`buildFont(bitmap, entries = [], order = 'BRG', layout = 'planar')`と`buildFontFromRom(bytes)`はTTFのUint8Arrayを返します。`bitmap`には同梱の`assets/x1-font.json`相当の配列、または読み込んだ独自フォントの配列を渡します。PCGには先に`pcg.js`を読み込んでください。別のwindow由来のROMは、そのiframe内の`Uint8Array.from(bytes)`で渡します。Node側の`require('./src/font-builder.cjs')`は従来どおりBufferを返します。

通常文字の合成プレビューは内蔵ビットマップを直接使い、独自フォントでは`readFontBitmap(bytes)`で本ビルダーのTTFから元のドットを復元します（非対応形式は`null`）。既存の`currentFont()` / `chooseFont()`の戻り値は変更不要です。本ビルダー以外の形式のTTFでは、通常文字を含む合成プレビューは表示せず、編集欄のフォント表示は維持します。`src/font-bitmap.js`は内蔵TTF・JSONと同じ元データから`npm run build:font`で生成します。

`contentChanged`は入力・貼り付け・切り取り・挿入・置換・Undo/Redo・新規作成・読み込みによる変更を通知します。同一バイトへの置換、同一内容の再読み込み、保存だけの操作、カーソル移動や表示設定は通知しません。未保存状態だけの変化は`state`で受け取ってください。コールバックの例外は編集欄に通知し、編集と保存は続行できます。

起動時、ホストの読み込みが非同期なら「初期の空文書」→「読み込んだ文書」の順で通知します。**ホストは自分の初期読み込みが終わるまで自動保存を抑制してください。** `onLoaded`の登録時に同期でデータを渡すホストでは、最初の通知がその文書になります。ホストからの読み込みも変更通知を発生させるため、自動保存ではその往復を考慮します。

アダプターと親iframeの通信・ファイル保管方法は取り込み側が担当します。この接続口はホストの起動前設定だけを行い、CSPの緩和や汎用postMessage受信は追加しません。右欄の幅調整もiframe内でそのまま使えます。

予約語の名称・綴りは、表示用の言語仕様データとして使用しています。生成元は同作者の [SLANG-compiler](https://github.com/h-o-soft/SLANG-compiler) の `HuKeywords.cs` で、参照ファイルのSHA-256を `src/keywords.js` の先頭コメントに記録しています。

予約語表を更新する場合は、参照する `HuKeywords.cs` を指定します。通常の起動時に元のコンパイラのファイルは必要ありません。

```sh
npm run update:keywords -- /path/to/SLANGCompiler.HuBasic/Lexing/HuKeywords.cs
```
